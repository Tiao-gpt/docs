# Threeebs :3 — Produto e formalização inicial do projeto

> Documento público de produto — primeira versão  
> Este documento descreve o produto de forma estável, sem amarrar a definição a preços, planos ou ao fluxo operacional temporário da Alpha.

---

# 1. O produto Threeebs

A Threeebs transforma uma ideia em um sistema próprio, funcional, hospedado e preparado para evoluir ao longo do tempo.

O produto geral combina:

```text
Ideia
  ↓
MVP funcional
  ↓
Hospedagem
  ↓
Subdomínio Threeebs
  ↓
Documentação do projeto
  ↓
Evolução contínua
```

Esses elementos fazem parte de uma mesma jornada.

Eles não precisam ser tratados como produtos isolados.

A cobrança, os planos e as condições comerciais são definidos separadamente da descrição do produto.

---

# 2. Começar simples

A Threeebs trabalha com a ideia de começar pela menor versão útil possível.

O primeiro objetivo não é construir tudo.

É colocar uma base funcional no ar.

```text
Ideia
  ↓
Primeira versão
  ↓
Uso real
  ↓
Aprendizado
  ↓
Melhorias
  ↓
Novas versões
```

Essa primeira versão pode ser:

- uma página;
- um website;
- um MVP;
- um sistema simples;
- uma estrutura inicial que valide uma ideia.

O importante é que ela já possa servir como base para crescimento.

---

# 3. Hospedagem

A hospedagem faz parte da estrutura central do produto.

O projeto pode permanecer hospedado na infraestrutura da Threeebs enquanto evolui.

A Threeebs assume, dentro dos limites do serviço contratado, a responsabilidade pela operação do ambiente.

Isso pode envolver:

- disponibilidade;
- infraestrutura;
- segurança;
- manutenção;
- backup;
- atualização do ambiente;
- suporte técnico.

A hospedagem não é apenas espaço em servidor.

Ela é parte da continuidade do projeto.

---

# 4. Subdomínio Threeebs

Projetos podem receber um endereço dentro da infraestrutura Threeebs.

Exemplo conceitual:

```text
projeto.3eb.site
```

O subdomínio funciona como um endereço inicial para publicação e uso do projeto.

Ele pode fazer parte da entrega do produto sem necessariamente representar uma cobrança independente.

---

# 5. Domínio personalizado

Projetos também podem utilizar um domínio próprio.

Exemplo:

```text
meuprojeto.com.br
```

O domínio personalizado é um recurso adicional ao endereço Threeebs.

Registro, configuração, manutenção e migração de domínio podem envolver serviços e custos específicos.

A documentação pública do produto não precisa fixar valores.

Os preços e condições comerciais devem ser consultados nos canais comerciais vigentes.

---

# 6. Documentação do projeto

Todo projeto na Threeebs começa com uma ideia ou necessidade.

O primeiro passo é entender o que está sendo construído e transformar isso em uma base clara de projeto.

A Threeebs trabalha junto nesse processo, ajudando a definir:

- objetivos;
- necessidades;
- prioridades;
- público;
- contexto;
- caminhos iniciais;
- possibilidades de evolução.

Cada projeto mantém sua própria documentação.

```text
Projeto
│
├── propósito
├── objetivos
├── contexto
├── público
├── prioridades
├── decisões
├── roadmap
└── referências
```

Essa documentação funciona como uma referência compartilhada entre o cliente e a Threeebs.

---

# 7. Documentação como contexto

A documentação não serve apenas para organização humana.

Ela também pode servir como contexto para ferramentas e agentes utilizados no desenvolvimento.

```text
Cliente
   │
   ▼
Documentação do projeto
   │
   ├── Threeebs
   ├── equipe
   ├── ferramentas
   └── agentes
```

Isso ajuda a preservar contexto ao longo do tempo.

Novas pessoas, ferramentas ou agentes podem compreender melhor:

```text
o que é o projeto
        ↓
por que ele existe
        ↓
o que já foi decidido
        ↓
para onde ele deve evoluir
```

---

# 8. Construção do MVP

A partir da documentação inicial, a Threeebs constrói uma primeira versão simples e funcional.

```text
Documentação
     ↓
Definição inicial
     ↓
MVP
     ↓
Publicação
     ↓
Uso
```

O MVP não precisa representar o produto final.

Ele representa o primeiro sistema utilizável.

Seu papel é permitir:

- colocar a ideia no ar;
- testar;
- apresentar;
- gerar primeiras interações;
- validar necessidades;
- iniciar uma evolução real.

---

# 9. Evolução contínua

Depois do MVP, o projeto pode continuar crescendo.

```text
MVP
 ↓
Feedback
 ↓
Atualização
 ↓
Nova funcionalidade
 ↓
Nova versão
 ↓
Sistema mais completo
```

A Threeebs não trata o projeto apenas como uma entrega única.

A ideia é que exista uma base capaz de receber melhorias ao longo do tempo.

Um projeto pode começar pequeno e posteriormente incorporar:

```text
Projeto
│
├── novas páginas
├── painel
├── usuários
├── banco de dados
├── automações
├── integrações
├── equipe
└── novos serviços
```

---

# 10. Sistema próprio

Um princípio importante do produto é a criação de sistemas próprios.

A ideia não é apenas configurar uma conta dentro de uma plataforma fechada.

O projeto deve possuir uma base técnica própria, capaz de ser versionada e evoluída.

```text
Projeto
  ↓
Código
  ↓
Repositório
  ↓
Histórico
  ↓
Evolução
```

Isso cria uma relação diferente com tecnologia.

O usuário começa a construir um ativo digital próprio.

---

# 11. Produto e cobrança são coisas diferentes

A definição do produto deve permanecer relativamente estável.

Os planos e preços podem mudar.

Por isso:

```text
PRODUTO
=
o que entregamos
+
como ajudamos
+
qual problema resolvemos
```

Enquanto:

```text
PLANO
=
limites
+
condições
+
recursos
+
preço
```

Um recurso pode fazer parte do produto e, dependendo do plano, ser:

- incluído;
- gratuito;
- limitado;
- adicional;
- contratado separadamente.

A documentação geral do produto não deve depender de preços fixos.

# 13. Síntese do produto

> **A Threeebs transforma ideias em sistemas próprios, começando por uma versão simples e funcional, hospedada e documentada, que pode evoluir ao longo do tempo.**

Em uma representação mais direta:

```text
IDEIA
  ↓
ENTENDIMENTO
  ↓
DOCUMENTAÇÃO
  ↓
MVP
  ↓
HOSPEDAGEM
  ↓
SISTEMA PRÓPRIO
  ↓
EVOLUÇÃO
```

Essa é a base do produto geral.

Planos, preços, limites e condições comerciais são camadas definidas separadamente.
